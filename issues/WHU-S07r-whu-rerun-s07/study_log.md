## Process findings

- 2026-10-28, step 2: `acquire_sources.robots_allow()` falsely refuses ipcc.ch. It reads robots.txt through `urllib.robotparser` with Python's default user agent; Cloudflare answers 403, and robotparser reads a 403 as "disallow all", so the auto-added WGIII SPM was reported "robots.txt disallows it". The robots.txt itself (fetched with a browser user agent) disallows only `/site/wp-admin/`. Every AR6 SPM added by fix 3 will be refused the same way on this network. No code change in this run; S006 was taken in by a person.
- 2026-10-28, step 3c: `coverage_check.py render` shortens a long declared unit with "…" inside the quotation marks, and `quotations.py` then BLOCKS that quotation ("quotations match the source") because "…" is not in the source. A declaration of a unit longer than the span limit therefore cannot pass the quotation row. In this run the two affected units (S001@18026-18259, S001@20151-20480) were stated on the page instead of declared. No code change.
- 2026-10-28, step 3c: `coverage_check.declaration_sentence` empties the quotation (renders “…”) when the source's label contains a full stop (e.g. a title "Transport. Climate Change 2022: …"), because the line must split as one sentence. Worked round by giving S001, S002 and S006 an `also_called` label without a full stop. No code change.
- 2026-10-28, step 3d: stating an SPM judgement binds a span inside its statement, which makes every sentence of that statement's detected extent a coverage unit. Several detected SPM extents run into neighbouring statements or figure captions (C.6.3 into C.7; C.7.3 into C.8; C.10.4 into the Figure SPM.6 caption, 26 fragments), so fix 3's "state it" path multiplies fix 2's coverage units. No code change; C.10.4 sent to a person.
- 2026-10-28, step 3c: binding a readers'-list declaration sentence to its unit's span makes that unit's group a coverage group (circular). Declaration rows are therefore framing rows (protected kind "scope"), their quotations checked by quotations.py.
