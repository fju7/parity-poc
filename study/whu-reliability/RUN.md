# Running WHU on one study question

From the question to "ready for operator acceptance", under "The frozen WHU process" (protocol rev 27) and the advisor's rulings of 20 October 2026 (below). Written for the practice run, `issues/WHU-P02-ultra-processed-foods/` (slug `ultra-processed-foods`). For a study question, replace the slug and the case directory; **every study issue directory is named `WHU-P…` or `WHU-S…`**, because the exclude entries (ruling 3) are keyed to those names.

**Ready for operator acceptance** means `publish.py check <slug>` prints `Ready.`: no row is a STOP, and the four excluded steps (outside review, adjudication verification, operator acceptance, publication) each read `SKIPPED — excluded from the frozen process for the study (protocol rev 27)`. A study answer is never published: `publish`, `update` and `announce` refuse it.

All commands run from the repository root with `backend/venv/bin/python3` (written `py` below). Never `--no-verify`, `--waive` or `WHU_SPEND_OVERRIDE`. Caps: the issue's $50 (`caps.json` `study_per_issue`) and the $25 day cap. If an answer can't finish within $50, that is a result: record it and stop; the limit is not raised.

## The private archive

The repository is public. Audit and ruling logs, and every file that quotes source passages, are never committed (ruling 3). `.gitignore` excludes, for every `issues/WHU-P*` and `issues/WHU-S*` directory: `audit/`, `rulings/`, `export/`, `bindings.json` (spans and envelopes), `gate-findings.json`, `quotations.json`, `conclusion-review.json`, `change-reviews.json`, and the gate reports `draft/*.gate.json*`. Committed: `issue.json`, `premise.json`, `sources.json`, the draft page (WHU's own prose; changecheck reads it from a commit), `study_log.md` and `private_manifest.txt`.

After the run (and after any day that ends mid-run), copy every excluded file to the private archive and commit only their sha256:

```
I=issues/WHU-P02-ultra-processed-foods
D=~/Projects/whu-study-private/WHU-P02-ultra-processed-foods/$(date -u +%Y%m%dT%H%M%SZ)
mkdir -p "$D"
git ls-files --others --ignored --exclude-standard "$I" | while read f; do mkdir -p "$D/$(dirname "$f")"; cp -p "$f" "$D/$f"; done
(cd "$D" && find . -type f | sort | xargs shasum -a 256) > "$I/private_manifest.txt"
git add "$I/private_manifest.txt" && git commit -m "WHU-P02: private archive manifest"
```

## A day-cap stop

**The stage-level cap check (2026-10-20).** Before any paid stage starts (the gate, step 4; the source advocate, 4b; the conclusion judge, 6; the audit, 7, and its resume; changecheck, 9; and every `ruling.py` mode), `stage_cap.py` estimates the stage's cost from what such stages have measurably cost: the spend ledger's metered calls (per gate call, per conclusion-judge sentence, per advocate source, per changecheck run), the audit manifests (spend per sentence unit) and the ruling logs (spend per ruling), times the stage's units (calls, sentences, sources still to read, units still to audit, items to rule). If the estimate exceeds the cap remaining today or on the issue, the stage does not start: it prints `NOT STARTED`, the estimate and how it was computed, what remains today of the $25 day cap and what remains on the issue of its $50 cap, and exits 3. Nothing is spent. Record it as a study-log row and run the stage after 00:00 UTC (or, for the issue cap, the answer ends: see Caps above). To see an estimate without running anything: `py backend/scripts/whatholdsup/stage_cap.py ultra-processed-foods <stage> <units>`. The estimate is a mean, so a stage can still cost more; every paid call still checks both caps, and a stage stopped mid-way is resumed as below.

The $25 day cap is below the audit's projected $31, so step 7 is expected to stop once. A stopped run's manifest has `"status": "failed"` and `"stopped_by": "day cap"` (or `"issue cap"`, which ends the answer: see Caps above).

- After 00:00 UTC, resume it in its own directory: `py backend/scripts/whatholdsup/audit_stage.py run ultra-processed-foods --resume issues/WHU-P02-ultra-processed-foods/audit/<UTC stamp> --cap 50`. It reads no finished sentence again, and it refuses if the page, bindings, held texts, prompts, model or seed changed since the stop.
- **The source advocate (step 4b)** saves each source's brief (its objections) when the call that drafted it returns, and each quotation check when it is decided, in `advocate/runs/<UTC stamp>/` (`inputs.json`, `briefs.jsonl`, `quote_checks.jsonl`, `state.json`; never committed). A cap stop marks the run `"stopped"`, prints the resume command and exits 3. After 00:00 UTC: `py backend/scripts/whatholdsup/source_advocate.py run ultra-processed-foods --page issues/WHU-P02-ultra-processed-foods/draft/ultra-processed-foods.html --resume <UTC stamp>`. It never drafts a saved brief or repeats a saved check again, and it refuses if the page body, the sources, a held text, a prompt or the model changed since the stop. A brief whose call returned nothing usable is not saved and is asked again. The run stopped on 2026-10-20 at 20:36Z predates this and saved no briefs: it is run again in full.
- A gate or ruling call stopped by the day cap is run again the next day.

## Withdrawing and superseding earlier work

When a run has to start again from records that must no longer count (as on 2026-10-20 for the WHU-P02 clean re-run), nothing is deleted:

- **Audit runs** are withdrawn: `py backend/scripts/whatholdsup/audit_stage.py withdraw ultra-processed-foods <UTC stamp> --reason "<why>"`. A run withdrawn twice keeps every reason with its date (`withdrawn.reasons`, oldest first); its rulings are no longer expected on the page and it is never the run the preflight reads.
- **Rulings and decision records** are superseded: `py backend/scripts/whatholdsup/supersede.py ultra-processed-foods --reason "<why>" --by "Claude Code (session <id>)"`. Every record in `rulings/rulings.jsonl`, `rulings/applied_check.jsonl`, `change-reviews.json`, `conclusion-review.json`, `gate-findings.json` and the advocate's briefs and adjudication is stamped `"superseded": {reason, on, by}` and the file is moved to `rulings/superseded/` or `advocate/superseded/` under a UTC-stamp prefix, with a line in that folder's `README.txt`; no current tool reads those folders. `--only` limits it to named records. When an advocate adjudication file is superseded and its briefs stay in place, a fresh blank template is written in its place (`source_advocate.write_template`, same name, same day), every item open, so `ruling.py advocate` finds them; with the briefs superseded too, none is written. Study issues only. `--by` is the agent's own name; a person's name needs `--signature <path>:<line>` (process doc section 8).
- Copy everything excluded to the private archive first (above), and record both as study-log rows.

## Rulings (advisor, 2026-10-20)

1. **Applied ruling text.** Accepted ruling text is applied word for word by the drafting session. A script then checks that each applied sentence on the page equals the ruling's text exactly, and logs it: `applied_check.py` (steps 5a, 6a, 7b), log `rulings/applied_check.jsonl`, exit 1 on any mismatch. It reads every accept or amend ruling in `rulings/rulings.jsonl` and `audit/*/rulings.jsonl`, expects only the last text where one ruling's text was ruled on again, skips a wording the audit left for a person, and compares as changecheck normalises (sentence splitting, whitespace) and no further.
2. **Gate run limits: no override.** A sentence still failing after the third gate run is cut, the cut is logged, and the answer continues. `--past-cap` and `--past-issue-cap` are never used.
3. **Logs and source quotations are never committed** (the repository is public). The exclude entries are in `.gitignore` (above). After a run the logs are copied to `~/Projects/whu-study-private/<issue>/`, and only a manifest of their sha256 is committed.
4. **`study_log.md`:** one row per stage — stage, start and end (UTC, from the clock), metered spend (from the ledger), operator minutes, outcome. Kept by the drafting session.
5. **Changecheck coverage.** After the final changecheck, a script confirms that changecheck read every body sentence changed since the first full draft (step 3b), and reports any it missed: `changecheck_coverage.py` (step 9a), exit 1 on any miss. It takes the changed sentences from changecheck's own `changed()` against the step-3b commit, and the read set from the fingerprints each changecheck run now records (`read`, with `model_read`; a `--no-model` run reads nothing).
6. **Conclusion judge on Q2.** It was calibrated partly on T02's sentences, so on Q2 it is not out of sample. This applies to the practice run only.
7. **The paid gate's web search** is part of WHU's process and stays.
